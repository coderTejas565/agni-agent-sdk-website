# RunResult

`RunResult` is the normalized result returned by [`Runner.run()`](/docs/api-reference/runner).

Every agent execution returns a `RunResult` describing whether the execution succeeded or failed.

The result is a **discriminated union**:

* `success: true` → successful execution with `output`
* `success: false` → failed execution with structured `error`

This makes runtime handling predictable and type-safe.

---

## Import

```ts
import type { RunResult } from 'agni-agent-sdk';
```

---

# Type Definition

```ts
type RunResult<TOutput = string> =
  | RunSuccess<TOutput>
  | RunFailure;
```

### Successful result

```ts
interface RunSuccess<TOutput> {
  success: true;

  output: TOutput;

  metadata?: RunMetadata;
}
```

### Failed result

```ts
interface RunFailure {
  success: false;

  error: RunError;

  metadata?: RunMetadata;
}
```

---

# Example

```ts
const result = await runner.run(
  agent,
  'Explain AI agents.',
  {
    context: {},
  },
);

if (result.success) {
  console.log(result.output);
} else {
  console.error(result.error.code);
  console.error(result.error.message);
}
```

Because `success` is the discriminant, TypeScript automatically knows which properties are available.

---

# Properties

## `success`

Indicates whether the agent execution completed successfully.

```ts
result.success;
```

**Type**

```ts
true | false;
```

When `success` is `true`, `result.output` is available.

When `success` is `false`, `result.error` is available.

---

## `output`

The final output produced by the agent.

```ts
result.output;
```

**Available when**

```ts
result.success === true;
```

**Type**

```ts
TOutput;
```

Example:

```ts
if (result.success) {
  console.log(result.output);
}
```

Example result:

```ts
{
  success: true,

  output:
    'The weather in Pune is sunny.',

  metadata: {
    runId: 'a10bd101-6254-4d5b-bc03-b1272b7adda6',
    turns: 2,
  },
}
```

---

## `error`

Contains structured information about an execution failure.

```ts
result.error;
```

**Available when**

```ts
result.success === false;
```

**Type**

```ts
RunError;
```

Example:

```ts
if (!result.success) {
  console.error(result.error.code);
  console.error(result.error.message);
}
```

A `RunError` contains:

```ts
interface RunError {
  code: RunErrorCode;

  message: string;

  metadata?: Record<string, unknown>;

  retryable: boolean;
}
```

---

## `error.code`

Stable machine-readable error code.

```ts
result.error.code;
```

Example:

```ts
if (!result.success) {
  if (result.error.code === 'PROVIDER_RATE_LIMIT_ERROR') {
    // Handle rate limiting
  }
}
```

Common codes currently produced by the runtime include:

* `AGNI_ERROR`
* `PROVIDER_ERROR`
* `PROVIDER_AUTHENTICATION_ERROR`
* `PROVIDER_RATE_LIMIT_ERROR`
* `PROVIDER_TIMEOUT_ERROR`
* `PROVIDER_RESPONSE_ERROR`
* `TOOL_NOT_FOUND`
* `TOOL_EXECUTION_ERROR`
* `TOOL_VALIDATION_ERROR`
* `TOOL_REGISTRATION_ERROR`
* `VALIDATION_ERROR`
* `GUARDRAIL_ERROR`
* `CANCELLED`
* `MAX_TURNS_EXCEEDED`

See [`Error`](/docs/api-reference/error) for the complete error system.

---

## `error.message`

Human-readable explanation of the failure.

```ts
result.error.message;
```

Example:

```text
Provider request timed out.
```

Use the message primarily for logging and debugging.

For programmatic handling, prefer `error.code`.

---

## `error.metadata`

Additional debugging information associated with the failure.

```ts
result.error.metadata;
```

**Type**

```ts
Record<string, unknown> | undefined;
```

Example:

```ts
{
  toolName: 'get_weather',
  runId: 'a10bd101-6254-4d5b-bc03-b1272b7adda6'
}
```

Metadata depends on the error type.

---

## `error.retryable`

Indicates whether retrying the failed operation may succeed.

```ts
result.error.retryable;
```

**Type**

```ts
boolean;
```

Example:

```ts
if (!result.success && result.error.retryable) {
  // Retry according to your application's retry policy.
}
```

Retryability is determined by the runtime error type.

For example:

* Provider rate limits → retryable
* Provider timeouts → retryable
* Authentication failures → not retryable
* Guardrail blocks → not retryable

---

# `metadata`

Contains information about the agent execution.

```ts
result.metadata;
```

**Type**

```ts
RunMetadata | undefined;
```

Example:

```ts
{
  runId: 'a10bd101-6254-4d5b-bc03-b1272b7adda6',

  turns: 2,
}
```

---

# RunMetadata

```ts
interface RunMetadata {
  runId?: string;

  turns?: number;

  durationMs?: number;
}
```

---

## `runId`

Unique identifier for the execution.

```ts
result.metadata?.runId;
```

Use the run ID for:

* Logging
* Debugging
* Correlating runtime events
* Observability
* Distributed tracing

Example:

```ts
console.log(result.metadata?.runId);
```

---

## `turns`

Number of execution turns completed.

```ts
result.metadata?.turns;
```

**Type**

```ts
number | undefined;
```

A turn represents one iteration of the agent execution loop.

For example:

```text
User Input
    |
    v
Provider
    |
    v
Tool Call
    |
    v
Tool Result
    |
    v
Provider
    |
    v
Final Response
```

An execution involving two provider iterations may produce:

```ts
{
  turns: 2,
}
```

---

## `durationMs`

Total execution duration in milliseconds.

```ts
result.metadata?.durationMs;
```

**Type**

```ts
number | undefined;
```

This field can be used for runtime performance monitoring.

---

# Successful execution

A successful execution returns `success: true` and the generated output.

```ts
{
  success: true,

  output:
    'The weather in Pune today is sunny.',

  metadata: {
    runId:
      '2389c130-8624-4232-8c69-3dffadf4ac6d',

    turns: 2,
  },
}
```

TypeScript narrows the result automatically:

```ts
if (result.success) {
  // result.output is available here
  console.log(result.output);
}
```

---

# Failed execution

A failed execution returns `success: false` and a structured `RunError`.

```ts
{
  success: false,

  error: {
    code: 'PROVIDER_RATE_LIMIT_ERROR',

    message:
      'Provider rate limit exceeded.',

    retryable: true,
  },

  metadata: {
    runId: '7c92d4d1',

    turns: 1,
  },
}
```

Handle failures using the error code:

```ts
if (!result.success) {
  switch (result.error.code) {
    case 'PROVIDER_RATE_LIMIT_ERROR':
      // Retry with backoff
      break;

    case 'PROVIDER_TIMEOUT_ERROR':
      // Retry according to application policy
      break;

    case 'TOOL_NOT_FOUND':
      // Check tool registration
      break;

    case 'GUARDRAIL_ERROR':
      // Tool execution was blocked
      break;

    case 'MAX_TURNS_EXCEEDED':
      // Runtime execution limit reached
      break;
  }
}
```

# Type-safe output

`Runner.run()` supports generic output types.

```ts
type WeatherResponse = {
  city: string;

  temperature: number;

  condition: string;
};

const result = await runner.run<WeatherResponse>(
  agent,
  'Weather in Pune',
  {
    context: {},
  },
);
```

When the execution succeeds:

```ts
if (result.success) {
  result.output.city;
  result.output.temperature;
  result.output.condition;
}
```

The output is therefore strongly typed as:

```ts
WeatherResponse;
```

---

# Handling results

A simple application-level pattern is:

```ts
const result = await runner.run(agent, input, {
  context: {},
});

if (!result.success) {
  throw new Error(
    `${result.error.code}: ${result.error.message}`,
  );
}

return result.output;
```

For production applications, prefer handling known error codes explicitly when retry or recovery behavior matters.

---

# Error handling with retryability

Agni exposes retryability through the normalized `RunError`.

```ts
const result = await runner.run(agent, input, {
  context: {},
});

if (!result.success) {
  if (result.error.retryable) {
    console.log('The operation may be retried.');
  } else {
    console.log('Retrying may not help.');
  }
}
```

Applications should still apply their own retry policy, including:

* Maximum retry attempts
* Exponential backoff
* Jitter
* Request deadlines

---

# Lifecycle

A `RunResult` is returned after the runtime completes an execution.

```text
Agent
  |
  v
Runner.run()
  |
  v
RunContext
  |
  v
Provider
  |
  v
Tool Execution
  |
  v
Provider
  |
  v
Execution Complete
  |
  v
RunResult
```

The result represents the final outcome of that execution.
