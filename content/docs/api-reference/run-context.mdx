# RunContext

`RunContext` represents the execution state of a single agent run.

It provides a shared context object that flows through the entire runtime lifecycle.

Use `RunContext` when your agent needs access to:

- Request metadata
- User-specific state
- Tool execution data
- Runtime information
- Custom application data

Each execution receives its own isolated context.

---

## Import

```ts
import type { RunContext } from "agni-sdk";
````

---

# Overview

When an agent starts executing, Agni creates a `RunContext`.

The context travels through:

```text
User Input

    |

    v

Runner

    |

    v

RunContext

    |

    +----------------+

    |                |

 Provider          Tools

    |                |

    +----------------+

            |

            v

      Final Result
```

This allows every part of the runtime to access execution-scoped information without relying on global state.

---

# Type Definition

```ts
interface RunContext<T = unknown> {

  runId: string;

  context: T;

  metadata?: Record<string, unknown>;

}
```

---

# Properties

## `runId`

Unique identifier for the current execution.

```ts
context.runId
```

**Type**

```ts
string
```

Example:

```ts
"a10bd101-6254-4d5b-bc03-b1272b7adda6"
```

Use this identifier for:

* Logging
* Tracing
* Debugging
* Correlating events

---

## `context`

Application-defined execution data.

```ts
context.context
```

**Type**

```ts
T
```

The value is provided when calling `runner.run()`.

Example:

```ts
const result = await runner.run(

  agent,

  "Book my flight",

  {

    context: {

      userId: "user_123",

      plan: "pro",

    },

  }

);
```

Tools can use this data during execution.

---

## `metadata`

Optional runtime metadata.

```ts
context.metadata
```

**Type**

```ts
Record<string, unknown> | undefined
```

Use metadata for additional execution information.

Example:

```ts
{

  requestId: "req_123",

  source: "api",

}
```

---

# Using Context in Tools

Tools receive the current execution context.

Example:

```ts
const userProfileTool = {

  name: "get_profile",

  description:
    "Returns user profile information.",


  async execute(
    args,
    context
  ) {

    const userId =
      context.context.userId;


    return {
      userId,
      name: "Tejas",
    };

  },

};
```

The tool can access the same context created by the Runner.

---

# Providing Context

Context is passed when executing an agent.

```ts
const result = await runner.run(

  agent,

  "Show my account details",

  {

    context: {

      userId: "user_123",

      role: "admin",

    },

  }

);
```

---

# Type-safe Context

You can provide your own context type.

```ts
type AppContext = {

  userId: string;

  organizationId: string;

};


const result = await runner.run<AppContext>(

  agent,

  "Generate report",

  {

    context: {

      userId: "user_123",

      organizationId: "org_456",

    },

  }

);
```

This gives your tools and runtime full type safety.

---

# Lifecycle

A RunContext exists only during one execution.

```text
Created

  |

  v

Agent Started

  |

  v

Tools Access Context

  |

  v

Provider Calls

  |

  v

Execution Complete

  |

  v

Destroyed
```

Context is not persisted between runs.

For persistent state, use:

* Memory
* Session storage
* External databases
