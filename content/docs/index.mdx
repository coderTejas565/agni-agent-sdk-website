# Build reliable AI agents with control

Agni Agent SDK is a **TypeScript-first runtime** for building production-ready AI agents that are predictable, observable, and easy to debug.

Unlike traditional agent frameworks that hide execution behind abstractions, Agni gives you explicit control over every step of an agent run—from provider requests to tool execution and runtime events.

# Your First Agent

Every Agni application is built around three core primitives.

## Agent

Defines your agent's identity, instructions, and capabilities.

↓

## Provider

Connects Agni to an AI model.

↓

## Runner

Executes the complete runtime lifecycle.

```ts
import 'dotenv/config';

import { Agent, Runner, GeminiProvider } from 'agni-agent-sdk';

const provider = new GeminiProvider({
  apiKey: process.env.GEMINI_API_KEY!,
});

const agent = new Agent({
  name: 'assistant',

  instructions: 'You are a helpful AI assistant.',

  provider,
});

const runner = new Runner();

const result = await runner.run(agent, 'Explain how AI agents work.', {
  context: {},
});

if (result.success) {
  console.log(result.output);
}
```

---

# What Happens During a Run?

Every call to `runner.run()` follows the same execution lifecycle.

```text
1. Create RunContext
        │
        ▼
2. Send messages to Provider
        │
        ▼
3. Provider decides whether tools are needed
        │
        ▼
4. Execute requested tools
        │
        ▼
5. Provider generates the final response
        │
        ▼
6. Return a normalized RunResult
```

This predictable runtime is the foundation of Agni.

---

# Runtime Architecture

Agni separates agent execution into independent layers.

```text
             User Input
                  │
                  ▼
               Runner
        ┌─────────┼─────────┐
        ▼         ▼         ▼
     Agent    Provider    Tools
        └─────────┼─────────┘
                  ▼
             Final Result
```

Each layer has a single responsibility.

- **Runner** orchestrates execution.
- **Agent** defines behavior.
- **Provider** communicates with the language model.
- **Tools** extend what the agent can do.

This architecture keeps your application independent from model providers while making every execution step observable.

# Why Agni?

Most agent frameworks abstract away the runtime.

Agni makes execution explicit.

You always know:

- when an agent starts
- when a provider is called
- when tools execute
- when a new runtime turn begins
- how the final response is produced

Because reliable AI systems require visibility, not hidden abstractions.

---

# Designed for Production

Agni is built around a small set of composable primitives.

- TypeScript-first APIs
- Provider-agnostic architecture
- Tool-first execution model
- Event-driven runtime
- Observable execution lifecycle
- Predictable agent behavior

Whether you're building a simple assistant or a production-grade multi-agent system, Agni provides the runtime not the magic.
