# Streaming

Agni provides two ways to observe an agent execution:

- **Runtime events** through the `EventBus`
- **Model streaming** through `runner.stream()`

Runtime events describe what the runtime is doing.

Model streaming exposes generated model output incrementally as it becomes available.

These are related, but they solve different problems.

---

## Why streaming exists

A normal agent execution waits for the provider to return a complete response.

```ts
const result = await runner.run(
  agent,
  'Explain AI agents.',
  {
    context: {},
  },
);
````

The application receives the final result after generation completes.

With streaming, the application can consume the response incrementally.

```ts
const stream = runner.stream(
  agent,
  'Explain AI agents.',
  {
    context: {},
  },
);

for await (const event of stream) {
  if (event.type === 'text_delta') {
    process.stdout.write(event.text);
  }
}
```

This is useful for:

* Chat interfaces
* Live response rendering
* Terminal applications
* Server-sent events
* WebSocket applications
* Responsive AI applications

---

## Two runtime observation systems

Agni separates runtime lifecycle events from model output streaming.

```text
                         Agent Execution
                               |
                +--------------+--------------+
                |                             |
                v                             v
            EventBus                    Provider.stream()
                |                             |
                v                             v
        Runtime Events               ModelStreamChunk
                                              |
                                              v
                                           Runner
                                              |
                                              v
                                      RunStreamEvent
                                              |
                                              v
                                          Consumer
```

The two systems have different responsibilities.

### EventBus

The EventBus exposes runtime lifecycle events such as:

* `agent.started`
* `turn.started`
* `provider.request`
* `provider.response`
* `tool.called`
* `tool.completed`
* `agent.completed`

### `runner.stream()`

`runner.stream()` exposes model output incrementally.

The application consumes the stream using `for await...of`.

---

## Streaming architecture

The provider owns provider-specific streaming behavior.

The Runner does not know how Gemini, OpenAI, Anthropic, or another provider implements streaming.

Instead, providers convert their native streaming responses into Agni's normalized streaming contract.

```text
Provider SDK
     |
     v
Provider Adapter
     |
     v
ModelStreamChunk
     |
     v
Runner
     |
     v
RunStreamEvent
     |
     v
Application
```

This keeps the application independent from provider SDKs.

---

## Provider-level streaming

Every provider implements the `ModelProvider` interface.

```ts
interface ModelProvider {
  generate(
    request: ModelRequest,
  ): Promise<ModelResponse>;

  stream(
    request: ModelRequest,
  ): AsyncIterable<ModelStreamChunk>;
}
```

`generate()` produces a complete model response.

`stream()` produces normalized chunks incrementally.

For example, the Gemini provider uses Gemini's streaming API internally:

```ts
const responseStream =
  await this.client.models.generateContentStream({
    model: this.model,

    ...geminiRequest,
  });
```

The Gemini provider then converts Gemini responses into Agni's provider-agnostic stream chunks.

---

## Model stream chunks

Providers produce normalized `ModelStreamChunk` values.

```ts
type ModelStreamChunk =
  | TextStreamChunk
  | ToolCallStreamChunk
  | StreamDoneChunk;
```

These types live in Agni's core contracts.

---

## Text stream chunk

A text chunk represents a newly generated piece of model output.

```ts
interface TextStreamChunk {
  type: 'text_delta';

  text: string;
}
```

For example:

```ts
{
  type: 'text_delta',
  text: 'An AI agent'
}
```

A provider may produce multiple text chunks during one response.

```text
"An AI agent"
      +
" perceives"
      +
" its environment"
      +
" and acts."
```

The application can consume each chunk immediately.

---

## Tool-call stream chunk

Agni also defines a normalized representation for incremental tool-call information.

```ts
interface ToolCallStreamChunk {
  type: 'tool_call_delta';

  id?: string;

  name?: string;

  arguments?: string;
}
```

This abstraction allows providers to expose streaming tool-call information without exposing their provider-specific response format.

The normalized contract is already part of Agni's core types.

The current Gemini streaming implementation, however, primarily emits text chunks and the final `done` chunk.

---

## Stream completion

When provider streaming has finished, the provider emits a normalized `done` chunk.

```ts
interface StreamDoneChunk {
  type: 'done';
}
```

This tells the Runner that provider streaming has completed.

---

## Runtime stream events

The Runner converts provider-level `ModelStreamChunk` values into public Agni `RunStreamEvent` values.

```ts
type RunStreamEvent =
  | RunStreamTextEvent
  | RunStreamToolCallEvent
  | RunStreamDoneEvent;
```

The public stream events include the `runId`.

This allows applications to associate streamed output with the corresponding agent execution.

---

## Text stream event

```ts
interface RunStreamTextEvent {
  type: 'text_delta';

  runId: string;

  text: string;
}
```

Example:

```ts
{
  type: 'text_delta',
  runId: 'df458eda-fdcd-4717-86ae-a24bc83ef86a',
  text: 'An AI agent'
}
```

---

## Tool-call stream event

```ts
interface RunStreamToolCallEvent {
  type: 'tool_call_delta';

  runId: string;

  id?: string;

  name?: string;

  arguments?: string;
}
```

This represents incremental tool-call information.

The event is provider-agnostic.

---

## Done stream event

```ts
interface RunStreamDoneEvent {
  type: 'done';

  runId: string;
}
```

The Runner exposes this event when the provider reports that streaming has completed.

---

## Consuming a stream

Applications consume the stream using `for await...of`.

```ts
const stream = runner.stream(
  agent,
  'Explain what an AI agent is.',
  {
    context: {},
  },
);

for await (const event of stream) {
  if (event.type === 'text_delta') {
    process.stdout.write(event.text);
  }
}
```

The application does not need to know anything about Gemini's streaming response objects.

It only handles Agni's `RunStreamEvent` values.

---

## Complete example

```ts
import {
  Agent,
  GeminiProvider,
  Runner,
} from 'agni-agent-sdk';

const provider = new GeminiProvider({
  apiKey: process.env.GEMINI_API_KEY,
});

const agent = new Agent({
  name: 'stream-test',

  instructions:
    'You are a helpful assistant. Keep responses concise.',

  provider,
});

const runner = new Runner();

const stream = runner.stream(
  agent,

  'Explain what an AI agent is.',

  {
    context: {},
  },
);

for await (const event of stream) {
  if (event.type === 'text_delta') {
    process.stdout.write(event.text);
  }
}
```

The application receives text incrementally instead of waiting for the complete model response.

## Streaming lifecycle

The current streaming execution follows this flow:

```text
Agent
  |
  v
RunContext
  |
  v
Provider.stream()
  |
  v
ModelStreamChunk
  |
  v
Runner
  |
  v
RunStreamEvent
  |
  v
Consumer
```

The Runner also publishes normal runtime lifecycle events through the EventBus.

Therefore, a streaming execution can be observed through both systems:

```text
                    Runner
                       |
          +------------+------------+
          |                         |
          v                         v
      EventBus                runner.stream()
          |                         |
          v                         v
 Runtime lifecycle             Model output
      events                     events
```

---

## EventBus vs streaming

The EventBus and model streaming should not be confused.

| EventBus              | `runner.stream()`       |
| --------------------- | ----------------------- |
| Runtime lifecycle     | Model output            |
| Observability         | Incremental generation  |
| Tool execution events | Text deltas             |
| Provider lifecycle    | Stream completion       |
| Logging               | Chat UI                 |
| Metrics               | Live response rendering |

For example, an application can listen for tool execution events:

```ts
runner.events.on('tool.called', (event) => {
  console.log('Tool:', event.toolName);
});
```

While simultaneously consuming model output:

```ts
for await (const event of runner.stream(
  agent,
  input,
  { context: {} },
)) {
  if (event.type === 'text_delta') {
    process.stdout.write(event.text);
  }
}
```

The EventBus tells you what the runtime is doing.

The stream tells you what the model is generating.

---

## Provider independence

The application never consumes provider-specific streaming objects.

For example, Gemini internally produces:

```text
Gemini SDK
    |
    v
GeminiProvider
    |
    v
ModelStreamChunk
    |
    v
Runner
    |
    v
RunStreamEvent
```

Another provider can implement the same contract:

```text
Provider SDK
    |
    v
Provider Adapter
    |
    v
ModelStreamChunk
    |
    v
Runner
    |
    v
RunStreamEvent
```

The Runner and application do not need to change.

This is the main benefit of Agni's provider abstraction.

---

## Error handling

Streaming provider failures are surfaced through the async generator.

Applications can handle them with `try/catch`.

```ts
try {
  for await (const event of runner.stream(
    agent,
    input,
    { context: {} },
  )) {
    if (event.type === 'text_delta') {
      process.stdout.write(event.text);
    }
  }
} catch (error) {
  console.error(error);
}
```

Provider-specific failures are normalized into `ProviderError` before being surfaced by the Runner.

The current streaming implementation does not return a `RunResult` when a provider failure occurs during streaming.

---

## Current implementation

The current Agni streaming implementation supports:

* Provider-agnostic streaming contracts
* Gemini streaming
* Incremental text events
* Stream completion events
* Run IDs on public stream events
* Provider error normalization
* `AsyncIterable` consumption

The normalized contracts also define tool-call streaming events.

However, the current Gemini streaming implementation primarily emits:

```text
text_delta
    |
    | ... more text
    |
done
```

Full streamed tool execution is not yet part of the current Runner streaming loop.

---

## Streaming vs `run()`

Use `run()` when the application needs the final normalized result.

```ts
const result = await runner.run(
  agent,
  input,
  {
    context: {},
  },
);
```

Use `stream()` when the application needs incremental model output.

```ts
const stream = runner.stream(
  agent,
  input,
  {
    context: {},
  },
);
```

The distinction is:

```text
run()
  |
  v
Provider.generate()
  |
  v
ModelResponse
  |
  v
Tool loop
  |
  v
RunResult
```

while:

```text
stream()
  |
  v
Provider.stream()
  |
  v
ModelStreamChunk
  |
  v
RunStreamEvent
  |
  v
Consumer
```

## Design principles

### Provider agnostic

Applications consume Agni's normalized stream events rather than provider SDK objects.

---

### Incremental

Model output becomes available as soon as the provider produces it.

---

### Decoupled

Providers handle provider-specific streaming.

The Runner handles normalization.

Applications handle presentation.

---

### Correlatable

Every public stream event contains a `runId`.

This allows streamed output to be associated with the corresponding runtime execution.

---

### Extensible

The normalized streaming contracts allow additional providers and streaming capabilities to be added without changing the application-facing API.
